#01BadSuccessor kya hai?

Core concept aur attack ki background — yahan se samajhna shuru karo

BadSuccessor ek Active Directory privilege escalation technique hai jo Windows Server 2025 mein introduce ki gayi ek nayi feature — delegated Managed Service Account (dMSA) — ko abuse karti hai.

🏢
dMSA kya hai?
Ek AD object jo service accounts ko migrate karne ka legitimate tarika deta hai. Naya account purane account ke privileges "inherit" kar sakta hai.
⚠️
Vulnerability
Agar low-priv user ke paas kisi OU mein CREATE_CHILD permission hai, wo wahan ek malicious dMSA bana ke kisi bhi account — jaise Administrator — ko impersonate kar sakta hai.
🔑
Key Attribute
msDS-ManagedAccountPrecededByLink attribute set karke attacker KDC ko convince karta hai ki dMSA ek high-priv account ka "successor" hai.
🎯
Impact
Low-priv domain user se direct Domain Admin access — bina password crack kiye, bina lateral movement ke.

#03Attack Ki Theory

Kerberos ticket chain — teen stages mein poora attack

A
dMSA Weaponize karna
LabOU mein ek naya dMSA object banao (hex_dmsa$) aur uska msDS-ManagedAccountPrecededByLink attribute Administrator account ki DN pe set karo. Ab KDC ko lagega ki ye dMSA Administrator ka legitimate "successor" hai.
B
tbyte ka TGT lena (tgtdeleg)
Rubeus ki tgtdeleg command Kerberos unconstrained delegation ka abuse karti hai — tbyte ka TGT directly memory se export hota hai. Ye TGT aage ke steps mein use hoga.
C
hex_dmsa$ ka krbtgt TGS lena (asktgs /targetuser)
tbyte ke TGT se hex_dmsa$ account ke liye krbtgt service ticket maango. KDC Administrator ke privileges ke saath ye ticket issue kar deta hai (kyunki hex_dmsa$ uska "successor" hai).
D
CIFS ticket lena — DC ka file system access
Step C se mila TGT use karke DC ka CIFS (SMB file sharing) service ticket maango. Ye ticket memory mein inject hota hai (/ptt) aur phir \\DC\C$ directly access ho jaata hai.
Ticket Chain Summary tbyte TGT → hex_dmsa$ krbtgt TGS → hex_dmsa$ CIFS TGS → DC C$ Access → flag.txt

STEP 3tbyte ka TGT capture karo (variable mein)

/nowrap flag base64 ek line mein deta hai — lekin terminal wrapping hoti hai. Isliye output ko variable mein capture karo aur manually extract karo.

PowerShell
PS C:\PoC> $output = & .\Rubeus.exe tgtdeleg /nowrap PS C:\PoC> $idx = ($output | Select-String -Pattern "base64\(ticket.kirbi\):").LineNumber PS C:\PoC> $b64 = ($output[$idx..($output.Count-1)] | ForEach-Object { $_.Trim() }) -join "" PS C:\PoC> $b64 = $b64 -replace '\s','' PS C:\PoC> $b64.Length 1968 ← 1500+ hona chahiye, sahi hai!
Why variable method? Out-File terminal width ke hisaab se lines pad karta hai spaces se — isiliye regex match fail hota hai. Variable mein capture karne par saaf data milta hai.
STEP 4.kirbi binary file banao

Base64 string ko binary .kirbi file mein convert karo — Rubeus file path directly accept karta hai.

PowerShell
PS C:\PoC> [System.IO.File]::WriteAllBytes("C:\PoC\delegated.kirbi", [System.Convert]::FromBase64String($b64)) PS C:\PoC> (Get-Item C:\PoC\delegated.kirbi).Length 1474 ← Valid kirbi file!

#06Flag & Summary

Attack successful — kya achieve kiya?

// ATTACK RESULTS
tbyte (low-priv user) se shuru kiya
LabOU pe CREATE_CHILD permission identify ki
hex_dmsa$ dMSA create karke Administrator impersonate karne ke liye weaponize kiya
Kerberos ticket chain: tbyte TGT → hex_dmsa krbtgt TGS → CIFS TGS
DC-LAB2025-01 ke C$ share tak administrator-level access mila
Administrator desktop ka flag.txt read kiya
Windows vs Linux Difference Windows method mein 3 Rubeus commands chahiye (tgtdeleg → asktgs krbtgt → asktgs cifs). Linux mein bloodyAD ek hi command mein dMSA create + TGT generate karta hai, phir Impacket se CIFS ticket + secretsdump se saare hashes milte hain — aur phir Pass-the-Hash se direct shell.
Mitigation Windows Server 2025 mein dMSA feature ko disable kar sakte hain ya OU level pe CREATE_CHILD permissions strictly control karein. Low-privilege users ko OU mein child object creation rights kabhi nahi deni chahiye.
