01

What is BloodHound & Why It Needs 2 Databases

BloodHound Active Directory ko ek graph ki tarah model karta hai — users, groups, computers, GPOs, sessions, permissions sab nodes aur edges ban jaate hain. Isse "kaun kis path se Domain Admin tak pahunch sakta hai" jaise complex questions ek click me answer ho jaate hain.

Architecture — 3 moving parts

ComponentKaam
Neo4jGraph database — poora AD data (nodes/edges/relationships) yahan store hota hai. Port 7687 (Bolt protocol) aur 7474 (web browser interface).
PostgreSQLBloodHound CE ka apna internal app-data database — users, sessions, API keys, job history, config. Port 5432.
BloodHound CE (bhapi)Actual web application/API jo dono databases se connect karke UI serve karta hai. Default port 8080.
Important: Teeno alag-alag services hain, teeno independently start honi chahiye. BloodHound CE in dono (Neo4j + PostgreSQL) se connect na ho paaye to start hi nahi hoga — yahi humari pichli session ka exact issue tha.
02

Installation

Kali par BloodHound CE aana prebuilt hota hai; agar nahi hai ya fresh install chahiye to:

Option A — Kali ka apt package (sabse simple)

ATTACKER BOX
sudo apt update
sudo apt install bloodhound -y
sudo apt install neo4j -y
sudo apt install postgresql -y

Yeh teeno dependencies ek saath install kar deta hai. Kali ke repos me BloodHound CE already hota hai.

Option B — Official Docker Compose (sabse clean, auto-managed)

ATTACKER BOX
curl -L https://ghst.ly/getbhce -o docker-compose.yml
docker compose up -d

Docker approach me Neo4j aur PostgreSQL dono containers ke andar hi managed hote hain — manual cluster/service start karne ki zaroorat nahi padti. Default admin password terminal output ya docker compose logs bloodhound me milta hai.

Recommended: Agar baar-baar yeh service-start issues face ho rahe hain, Docker Compose route is sab se bachata hai kyunki Docker khud dependencies manage karta hai.

Option C — Manual binary download

ATTACKER BOX
# GitHub releases se latest BloodHound CE binary download karo
# https://github.com/SpecterOps/BloodHound/releases
chmod +x bloodhound-linux-amd64
sudo mv bloodhound-linux-amd64 /usr/bin/bloodhound
03

Neo4j Setup

Neo4j ko pehle start aur configure karna hota hai, BloodHound se pehle.

Pehli baar start karo (console mode — foreground, debugging ke liye achha)

ATTACKER BOX
sudo neo4j console

Yeh foreground me chalta hai — terminal band karoge to Neo4j bhi band ho jayega. Logs seedhe terminal me dikhte hain, isliye pehli setup ke liye best hai.

Background/service mode (normal daily use)

ATTACKER BOX
sudo systemctl start neo4j
sudo systemctl enable neo4j   # boot par auto-start
sudo systemctl status neo4j

Pehli baar password set karo

Neo4j start hote hi http://localhost:7474 par browser me jaake default creds (neo4j/neo4j) se login karo — pehli login par naya password set karne ko kahega.

Browser
http://localhost:7474
Username: neo4j
Password: neo4j        # first login pe change karna padega
Yaad rakho: Yehi naya password bhapi.json config me bhi daalna padega (next section).
04

PostgreSQL Setup

Yeh wahi part hai jahan humari pichli session me problem aayi thi — isliye detail me.

Installed hai ya nahi check karo

ATTACKER BOX
dpkg -l | grep postgresql
which psql

Service start karo

ATTACKER BOX
sudo systemctl start postgresql
sudo systemctl enable postgresql
⚠ Trap: postgresql.service ek wrapper/meta service hai jo sirf per-version clusters ko trigger karta hai. Yeh khud "run" hoke turant exit ho jaata hai — status active (exited) dikhega, jiska matlab actual database chal hi nahi rahi!

Verify karo — yahi step humari asli diagnosis thi

ATTACKER BOX
pg_lsclusters

Output format: Ver Cluster Port Status Owner Data-directory Log-file. Agar Status column me down dikhe (ya row hi na ho), to yehi root cause hai.

Healthy output dikhna chahiye aisa
Ver Cluster Port Status Owner    Data directory              Log file
18  main    5432 online postgres /var/lib/postgresql/18/main /var/log/postgresql/postgresql-18-main.log

Cluster down ho to directly start karo

ATTACKER BOX
sudo pg_ctlcluster 18 main start
# version number apna actual version se replace karo (pg_lsclusters se pata chalega)

Yeh command wrapper service ko bypass karke directly us specific cluster ko start karta hai — jab tak port actually listen nahi karne lagta tab tak process foreground/background me zinda rehta hai.

Agar cluster exist hi nahi karta (bilkul fresh install)

ATTACKER BOX
sudo pg_createcluster 18 main --start

Confirm karo port par kuch listen kar raha hai

ATTACKER BOX
sudo ss -tulpn | grep 5432
Healthy output
tcp   LISTEN 0      200             127.0.0.1:5432       0.0.0.0:*    users:(("postgres",pid=89928,fd=7))
tcp   LISTEN 0      200                 [::1]:5432          [::]:*    users:(("postgres",pid=89928,fd=6))
Yeh dikhte hi: PostgreSQL ab ready hai, agla step BloodHound DB/user create karna (zaroorat pade to) ya seedha BloodHound start karna hai.

BloodHound ka DB aur user manually create karna (agar auto-setup nahi hua)

ATTACKER BOX
sudo -u postgres psql -c "\du"     # existing users dekho
sudo -u postgres psql -c "\l"      # existing databases dekho

Agar _bloodhound user ya bloodhound database missing hai, config file se exact credentials uthao:

ATTACKER BOX
cat /etc/bhapi/bhapi.json
ATTACKER BOX — psql shell
sudo -u postgres psql
psql prompt ke andar (config ki values use karo)
CREATE USER _bloodhound WITH PASSWORD 'bhapi.json_se_password';
CREATE DATABASE bloodhound OWNER _bloodhound;
\q
05

Starting Everything — Correct Order

Order matter karta hai — BloodHound dono databases ko already running expect karta hai startup par.

  1. Neo4j start karo pehle — sudo neo4j console ya sudo systemctl start neo4j. Wait karo jab tak "Started." log na dikhe.
  2. PostgreSQL verify/start karo — pg_lsclusters se confirm karo online hai; nahi to sudo pg_ctlcluster <ver> main start.
  3. Dono ports verify karo ek saath:
    ATTACKER BOX
    sudo ss -tulpn | grep -E "5432|7687"
  4. BloodHound CE start karo:
    ATTACKER BOX
    sudo bloodhound
    "It will take time, please wait..." message normal hai — pehli baar DB schema migrate ho raha hota hai.
  5. Logs me success confirm karo — error-free startup, aur http://localhost:8080 (ya jo port config me ho) khulne laga.
Quick one-liner: sudo neo4j console & sudo pg_ctlcluster 18 main start && sleep 5 && sudo bloodhound

Collecting Data — SharpHound

BloodHound sirf visualization/analysis tool hai — actual AD data **SharpHound** collector se gather hota hai, domain-joined machine ya domain user context se run karke.

Download

VariantDownload

Basic collection run (domain-joined Windows machine par)

Target/pivot Windows machine
SharpHound.exe -c All
FlagMatlab
-c AllSaare collection methods enable karo (Sessions, LocalAdmin, ACL, Trusts, GPO, ObjectProps, etc.) — sabse comprehensive run.
-c Session,LocalAdminSpecific methods sirf — stealthier/faster run jab pura collection nahi chahiye.

Output ek timestamped .zip file hoti hai (JSON files ka collection) — isi ko BloodHound UI me upload karna hai.

Ingesting Collected Data

  1. BloodHound UI me login karo (localhost:8080)
  2. Left sidebar me "File Ingest" / Upload section par jao
  3. SharpHound se mila .zip file select karke upload karo
  4. Processing complete hone ka wait karo — progress indicator dikhega
  5. Analysis tab me jaake pre-built queries use karo, jaise "Find Shortest Paths to Domain Admins"
Multiple collection runs same domain ke liye merge ho jaate hain — purana data overwrite nahi hota, naya add hota hai.

Troubleshooting — Har Common Error

In order se check karo — zyadatar BloodHound issues in hi 5 categories me aate hain.

⚠ Error: "connection refused" dial tcp 127.0.0.1:5432

(Humne abhi yehi debug kiya) — PostgreSQL port par koi listener nahi hai.

Fix
pg_lsclusters                              # cluster ka status check karo
sudo pg_ctlcluster <version> main start    # down ho to start karo
sudo ss -tulpn | grep 5432                 # verify listener

⚠ Error: "active (exited)" in systemctl status

Wrapper service khud exit ho gayi, actual cluster/process chalu nahi hai. Yeh sirf PostgreSQL ke saath nahi, kai Debian/Kali multi-instance services (jaise MySQL) ke saath bhi hota hai.

Fix
sudo systemctl restart postgresql@<version>-main
sudo systemctl status postgresql@<version>-main
# status "active (running)" dikhna chahiye, "(exited)" nahi

⚠ Error: Neo4j "failed to obtain lock" / won't start

Pichla Neo4j process properly close nahi hua, ya ek aur instance already chal rahi hai.

Fix
sudo ss -tulpn | grep 7687        # already running to hai?
ps aux | grep neo4j               # stuck process dhundo
sudo kill -9 <PID>
sudo rm /var/lib/neo4j/run/neo4j.pid   # agar stale lock file ho
sudo neo4j console

⚠ Error: BloodHound "unable to connect to neo4j" / auth failure

Config file ka Neo4j password actual Neo4j password se match nahi kar raha.

Fix
cat /etc/bhapi/bhapi.json    # config me diya password check karo
# Browser se http://localhost:7474 pe login karke confirm karo wahi password kaam karta hai
# Agar bhool gaye ho, Neo4j password reset karo:
sudo neo4j-admin dbms set-initial-password <naya_password>
# phir bhapi.json me bhi wahi password update karo

⚠ Error: BloodHound UI khulta hi nahi (localhost:8080 refused)

Fix
sudo ss -tulpn | grep 8080             # kuch listen kar raha hai?
sudo journalctl -u bloodhound -n 50    # agar systemd service hai to logs dekho
# ya agar foreground me chalaya tha, terminal output hi dekho error ke liye
Agar BloodHound crash ho raha hai startup ke turant baad, 90% cases me yeh Neo4j ya PostgreSQL dono me se ek down hona hota hai — Step 05 "Starting Everything" dobara follow karo.

⚠ Error: SharpHound.exe AV/Defender se block ho jaata hai

SharpHound ek well-known, signature-matched tool hai — yeh expected behavior hai, defensive tooling ka. Authorized engagement me client se exclusion allow karwao, ya authorized lab me Defender temporarily disable karo. In-conversation AV-evasion/obfuscation techniques yahan cover nahi ki gayi hain.

⚠ Error: ".zip upload fails / processing stuck" in UI

CauseFix
Corrupt/partial zipSharpHound run poora complete hone se pehle zip copy kiya gaya tha — re-run aur poora wait karo.
Neo4j full/out of memory during ingest/etc/neo4j/neo4j.conf me heap size badhao: dbms.memory.heap.max_size=2G (ya zyada), phir Neo4j restart karo.
Old BloodHound Legacy format file (not CE compatible)Purani BloodHound (legacy) SharpHound output BloodHound CE me directly upload nahi hoti — latest SharpHound release use karo jo CE schema match karta ho.

General diagnostic — jab bhi kuch samajh na aaye

ATTACKER BOX — ek saath sab check karo
pg_lsclusters                              # PostgreSQL status
sudo ss -tulpn | grep -E "5432|7687|7474|8080"   # sab 4 ports ek saath
sudo systemctl status neo4j postgresql     # dono services ka summary
sudo journalctl -xe --no-pager | tail -50  # recent system errors
