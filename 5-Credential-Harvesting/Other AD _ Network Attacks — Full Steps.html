🎯 Other AD / Network Attacks

Beyond local file/memory credential hunting, these techniques obtain credentials by attacking the Kerberos and NTLM authentication protocols directly across the victim network — Kerberoasting, AS-REP Roasting, SMB Relay, and LLMNR/NBNS Poisoning, with full attack steps.

Intro

Prerequisite Protocols

These attacks target network-facing Windows/AD authentication protocols instead of a single compromised machine's local files or memory. Before going further, it helps to understand two protocols:

  • Kerberos — AD's default authentication protocol. Involves a Ticket Granting Ticket (TGT) from the Key Distribution Center (KDC), then a Ticket Granting Service (TGS) ticket to access a specific service.
  • NTLM — an older challenge-response authentication suite, still used as a fallback in many environments; its weaknesses are what SMB Relay and LLMNR/NBNS poisoning abuse.
Attack 1

Kerberoasting

Kerberoasting targets accounts that have a Service Principal Name (SPN) set (e.g. an IIS, MSSQL, or custom service account). Any authenticated domain user can request a TGS ticket for an SPN account — that ticket is encrypted with the service account's own password hash, so it can be taken offline and cracked without touching the target again.

Full Steps

  1. Enumerate SPN accounts using any valid domain credentials: 
    python3.9 /opt/impacket/examples/GetUserSPNs.py -dc-ip <DC_IP> THM.red/thm
    This lists every account with a registered SPN, e.g. svc-user running http/creds-harvestin.thm.red.
  2. Request a TGS ticket for the discovered SPN account: 
    python3.9 /opt/impacket/examples/GetUserSPNs.py -dc-ip <DC_IP> THM.red/thm -request-user svc-user
    This returns a Kerberos ticket hash in the form: 
    $krb5tgs$23$*svc-user$THM.RED$THM.red/svc-user*$...
  3. Save the hash to a file (e.g. spn.hash).
  4. Crack it offline with Hashcat, mode 13100 (Kerberos 5 TGS-REP etype 23): 
    hashcat -a 0 -m 13100 spn.hash /usr/share/wordlists/rockyou.txt
  5. If the service account's password is weak, Hashcat recovers it in cleartext — giving direct access to that account, and a foothold for further privilege escalation or lateral movement.
📌 The attack's strength depends entirely on the SPN account's password strength — service accounts are often set once and never rotated, making them a common weak point.
Attack 2

AS-REP Roasting

This attack targets accounts with "Do not require Kerberos pre-authentication" enabled. Normally, Kerberos pre-auth requires proving knowledge of the password before the KDC issues anything. With this setting disabled, anyone can request an AS-REP response for that account — no credentials needed — and the response is encrypted with the account's password hash, crackable offline.

Full Steps

  1. Enumerate domain usernames during recon and build a user list, e.g.: 
    Administrator
admin
thm
test
sshd
victim
CREDS-HARVESTIN$
    Save this as users.txt.
  2. Run GetNPUsers against the list — no valid password is required for the vulnerable accounts: 
    python3.9 /opt/impacket/examples/GetNPUsers.py -dc-ip <DC_IP> thm.red/ -usersfile /tmp/users.txt
    For accounts that don't have the setting, the tool reports doesn't have UF_DONT_REQUIRE_PREAUTH set. For a vulnerable account, it returns a crackable hash: 
    $krb5asrep$23$victim@THM.RED:166c95418fb9dc495789fe9...1e8d2ef27$6a0e13abb5c99c07
  3. Export in cracking format if needed, using the -format argument (John or Hashcat formats are both supported).
  4. Crack the AS-REP hash offline with Hashcat or John: 
    hashcat -a 0 -m 18200 asrep.hash /usr/share/wordlists/rockyou.txt
  5. A weak password on the vulnerable account cracks straight to plaintext.
📌 Tools like Rubeus (Windows) can also harvest and crack these tickets; this is a pre-auth enumeration + offline crack pattern, same as Kerberoasting but without needing any valid credentials up front.
Attack 3

SMB Relay Attack

Abuses the NTLM challenge-response mechanism. Instead of cracking a captured hash, the attacker relays a victim's NTLM authentication attempt to another machine in real time, authenticating as the victim without ever knowing their password.

Full Steps (conceptual flow)

  1. Confirm SMB signing is disabled on target machines — this is a hard requirement; if signing is enforced, relayed authentication is rejected.
  2. Position as a Man-in-the-Middle on the local network to intercept SMB authentication traffic (commonly combined with LLMNR/NBNS poisoning, below, to lure victims into authenticating to the attacker).
  3. Capture the victim's NTLM authentication attempt as it occurs (e.g. when a victim's machine tries to browse a share or print to a spoofed resource).
  4. Relay that authentication to a different target machine where the victim's credentials are valid, rather than cracking the hash offline.
  5. If successful, the attacker gains an authenticated session on the relay target with the victim's privileges — potentially local admin, enabling further post-exploitation (e.g. dumping SAM, as covered in local credential tasks).
⚠️ This section stays at the conceptual/workflow level rather than specific relay-tool command syntax, since the operational detail of configuring and running a live MITM relay is squarely an attack-execution step rather than a "where do credentials live" lookup. For hands-on practice this is best done inside an authorized lab room (e.g. THM's Exploiting AD room, referenced in the source material) that walks through the specific tooling safely.
Attack 4

LLMNR / NBT-NS Poisoning

LLMNR (Link-Local Multicast Name Resolution) and NBT-NS (NetBIOS Name Service) are fallback name-resolution protocols: when DNS fails to resolve a hostname, a machine broadcasts a multicast request to the local network asking "who is this host?"

How the Attack Works

  1. A victim machine's DNS lookup fails for some hostname (can be organic, e.g. a typo'd share path, or triggered by the attacker).
  2. The victim machine falls back to broadcasting an LLMNR/NBT-NS request to the whole local segment.
  3. An attacker positioned on the same network segment answers the broadcast, falsely claiming to be the requested host (spoofing an authoritative source).
  4. The victim machine, believing it found the right host, sends its NTLM authentication (challenge-response) directly to the attacker.
  5. The attacker captures the NTLM hash from that exchange — to be cracked offline, or relayed live via an SMB Relay attack (above) for immediate access.
🎯 End goal of both SMB Relay and LLMNR/NBNS Poisoning: capture or relay a victim's NTLM authentication to gain access to their account or machine — without ever touching their actual password.
